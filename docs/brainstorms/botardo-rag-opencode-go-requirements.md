# Botardo: Real RAG + OpenCode Go Model

## Summary

Upgrade Botardo, the Cloudflare Worker chat assistant on ramirocerda.com, from a static embedded knowledge base and Llama 3.1 8B to a real retrieval-augmented pipeline: the profile knowledge is indexed in Cloudflare Vectorize, the most relevant chunks are retrieved per question, and answers are generated by DeepSeek V4 Flash served through the OpenCode Go subscription. The bot keeps its identity, conversation history, and error handling, but gains reliable language matching and always answers when the information exists.

---

## Problem Frame

Botardo currently answers from a flat 88-line knowledge base embedded directly in the Worker bundle (`workers/chat-worker/src/knowledge-base.ts`), with `@cf/meta/llama-3.1-8b-instruct-fp8` as the generator. In practice the 8B model cannot reliably follow the prompt's rule set: it answers in Spanish even when the visitor writes in English, and it sometimes produces no answer at all even when the requested information is present in the knowledge base.

Both defects share a root: a weak model paired with unranked context. The static KB gives retrieval no ranking — every question is matched against the whole flat blob and the model must extract the needle itself, which it frequently fails to do. The site presents Ramiro to an international audience, so English-language visitors are not an edge case; a Spanish-only reply (or a silence) directly undermines the page's purpose.

---

## Actors

- A1. Site visitor: person chatting with Botardo through the site widget; may write in Spanish or English.
- A2. Ramiro (maintainer): owns the site, the OpenCode Go subscription, and the Worker deployment.

---

## Key Flows

- F1. Answer a visitor question
  - **Trigger:** A1 sends a message in the chat widget.
  - **Actors:** A1, Botardo pipeline (A2 maintains it).
  - **Steps:** (1) Detect the language of the latest visitor message; (2) retrieve the top-k most relevant chunks from the vector index; (3) build the prompt from identity, conversation history, retrieved chunks, and the language instruction; (4) generate the answer with DeepSeek V4 Flash; (5) reply in the visitor's language.
  - **Outcome:** The visitor receives an answer in their language, grounded only in retrieved knowledge chunks — when nothing relevant matches, the model is instructed to say naturally that it does not have that information.
  - **Covered by:** R1, R2, R3, R4, R5, R8

---

## Requirements

**[Retrieval]**
- R1. The profile knowledge base content (experience, projects, stack, education) is indexed into Cloudflare Vectorize as searchable chunks; the content itself is unchanged from the current KB, only restructured.
- R2. Each visitor question retrieves the top-k most relevant chunks and injects them as the only factual context available to the generator.
- R3. Answers are grounded exclusively in the retrieved chunks: the model must not invent facts or use outside knowledge about Ramiro.

**[Language]**
- R4. The language of the visitor's latest message is detected and the answer is produced in that language — rioplatense voseo Spanish for Spanish, English for English — as a firm instruction, not a soft guideline.
- R5. The generator is a model from the OpenCode Go plan (DeepSeek V4 Flash, `deepseek-v4-flash`) that reliably follows the language and grounding instructions.

**[Behavior continuity]**
- R6. Conversation history behavior is preserved: the last 10 turns are included as context, as today.
- R7. Existing identity prompt, CORS handling, and rate-limit (429) and model-error (500) responses are preserved.

**[Fallback]**
- R8. When retrieval returns no relevant context for the question, Botardo still generates an answer: the prompt marks the context as empty ("sin contexto recuperado") and instructs the model to answer exclusively from retrieved context and to say naturally when it does not have that information — it never stays silent, refuses, or invents facts.

---

## Acceptance Examples

- AE1. **Covers R4.** Given a visitor sends "What projects has Ramiro built?" in English, the answer is in English.
- AE2. **Covers R4.** Given a visitor sends "¿Qué proyectos hizo Ramiro?" in Spanish, the answer is in rioplatense voseo Spanish.
- AE3. **Covers R2, R3, R8.** Given a question with no matching content in the knowledge base (e.g., an unrelated topic), Botardo answers gracefully that it does not have that information, in the visitor's language, and invents no facts — via the model's no-invent guardrail rather than a fixed message.
- AE4. **Covers R1, R2.** Given a question whose answer exists in the knowledge base (e.g., "¿Dónde trabajás?" / "Where do you work?"), Botardo always answers from the retrieved chunk, in either supported language.

---

## Success Criteria

- A visitor asking in English receives an English answer; a visitor asking in Spanish receives rioplatense voseo Spanish.
- Every question whose answer exists in the knowledge base produces an answer — no silent refusals.
- A downstream planner can turn this document into tasks (index construction, Worker pipeline change, model swap, secrets) without inventing product behavior; the acceptance examples are executable as tests.

---

## Scope Boundaries

- Index only the profile knowledge base — not the site's notes, blog, or project content.
- Do not touch the Coderhouse RAG project at `ai-engineering-coderhouse-course/pre-entrega-4` (Pinecone-based); its hybrid-retrieval concept may inform the design but it is not part of this work.
- No changes to the chat UI/UX on the site.
- No migration to a non-Go provider; the generation model comes from the OpenCode Go plan.
- No rewriting of the knowledge base content — only restructuring into indexed chunks.

---

## Key Decisions

- Generation model: DeepSeek V4 Flash (`deepseek-v4-flash`) via the OpenCode Go subscription — the cheapest included model, already used locally by Ramiro, and served through the OpenAI-compatible endpoint (`https://opencode.ai/zen/go/v1/chat/completions`).
- Vector store: Cloudflare Vectorize — native to the platform hosting the Worker, free tier, embeddings produced via Workers AI, no external index service.
- Language handling at two layers: a firm prompt instruction on the latest visitor message plus a model capable of following it.
- Retrieval flow follows the same shape as the Coderhouse project (retrieve relevant chunks, inject as context) but stays fully native to Cloudflare.

---

## Dependencies / Assumptions

- Active OpenCode Go subscription with an API key; the key is stored as a Worker secret, never in the repository.
- Cloudflare Vectorize is available on the account at the free tier.
- Embeddings are produced via Workers AI; the concrete embedding model and chunking strategy are chosen in planning.
- Expected traffic stays within the OpenCode Go plan usage limits.
