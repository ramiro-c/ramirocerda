🧪 Armé un harness para testear agentes sin usar un LLM como juez.

El problema que quería resolver: dos respuestas idénticas, dos veredictos distintos según el humor del juez. Si el test no es determinista no es un test.

Cómo funciona:

→ Golden cases en JSON con el transcript completo grabado: prompt, respuesta, tools llamadas con args y resultados
→ 6 graders programáticos: tool_usage (tools esperadas y prohibidas), tool_args, numeric_grounding (todo número de la respuesta tiene que salir de los resultados de una tool), fact_grounding (toda afirmación tiene que estar respaldada), no_forbidden_content (a prueba de acentos, mayúsculas y puntuación), language
→ Umbral de pass-rate con exit code para CI: si baja, el build se pone rojo
→ Sin LLM en el loop

La demo es un agente de soporte sintético con 8 casos: uno limpio y siete con un defecto diseñado a propósito. Uno menciona un ticket 9999 que nunca salió de la base de conocimiento: numeric_grounding lo ve solo. Otro responde en español un prompt que estaba en inglés: language lo agarra. Cada caso falla por su motivo y solo por ese.

No reemplaza todo juicio: no detecta tono, no atrapa paráfrasis y el detector de idioma es heurístico (es/en). El juez LLM sigue teniendo lugar, pero sobre un subconjunto chico y revisado, no como única pared entre un defecto y producción.

Ya lo estoy usando para evaluar contra golden set lo que genera spec-refinery, y las respuestas del rag-citation-agent, que solo puede citar fuentes que su usuario está autorizado a ver.

Repo con el código y la demo https://github.com/ramiro-c/agent-evals
